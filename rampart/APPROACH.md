# Rampart adaptation

This branch adds a candidate-library adapter without changing upstream source. Pinned upstream: 12af471f627f866411b4bd785b19646d3672784c. The MIT copyright and permission notice remain in LICENSE. These Rampart files are additions.

The useful methods are subject-specific art direction, a dedicated app-screen route, truthful charts/data, real app fragments inside marketing pages and named motion recipes. They complement task-driven structure and scoped revision methods. They do not assess advertising effects, brand strategy, social practice or campaign narrative.

```sh
python3 rampart/candidates.py --mode page --sector physical-product --have product-photo \
  --output /absolute/private/project/evaluation/candidates.json
python3 rampart/candidates.py --mode app --sector workspace \
  --output /absolute/private/project/evaluation/app-candidates.json
python3 -m unittest discover -s rampart -v
```

The adapter reads hash-pinned source libraries, preserves recipes as proposals and excludes page directions whose declared asset requirements are not met. It never broadens a failed asset gate to return something anyway. Empty results mean unresolved direction. Declared photography is not proof of suitable quality, rights or relevance.

Candidates are unselected. Human preferences have not been applied by this script. The maker must compare them to the actual task, approved identity and scoped taste, record the chosen relationships and author the portable handoff. Existing colors/type remain authoritative. Source-study claims are declarations until the underlying evidence is inspected. Candidate order is not a ranking.

No browser, installer, global history, media download or model API is used. The pinned checkout has 20 directions, 18 motion entries and seven app styles. It has the shared scene stage but no library/scenes.json or individual scene assets; do not claim a complete scroll-scene catalog. Direct-CDP inspection helpers are not part of this adapter. Use the host's supported browser controls for motion, layout, reduced-motion, offscreen behavior and actual task tests.

Keep private proposals outside this public checkout. No fixed animation counts, glass bans or mandatory random direction is imposed. A source recipe still needs subject-specific assets, timing, accessibility, implementation and finished-work review. A successful report is not a quality pass or a trained taste model.
